Folders

Looking at a folder, and copying, moving, renaming and deleting what is in it.

A folder holds files, and sometimes other folders. When you want to find a photo, tidy a pile of letters or clear out last year's downloads, you need to see what is there and then do something to it. Tuatara's file manager is called rimu. It shows a folder as a list, a line for each thing in it, and it lets you pick some of those lines and act on them. The picking works as it does in the buffer list of chapter 7, so most of what you learned there applies here.

This chapter starts with opening a folder and moving about in it. Then it shows how to change what the list shows, how to look at a file without opening it, and how to choose entries. The rest is what you can do with the choice: make, copy, move, rename, delete, pack into an archive and compare. Chapter 9 explained how to open a single file. This chapter is about many files at a time.

As in the other chapters, every key here is pressed in NORMAL state unless it starts with C-x. i starts INSERT state, and C-g or ESC returns to NORMAL. In a list you rarely need INSERT, because the keys are commands.

10.1 Opening a folder

C-x d asks which folder you want and lists it. The question already holds the folder of the buffer you are in, so you often only press RET. To go elsewhere, type the rest of a path, or start again from your home folder with ~/. TAB completes a name as you type it.

If you are looking at a file and want to see what else is in its folder, C-x C-j lists that folder with the cursor on the file. C-x 5 d does what C-x d does in a new window of its own.

From a terminal you can start Tuatara on a folder, for example with tuatara ~/Photos/holiday/, and the list is the first thing you see.

Figure 10.1 shows a list for a folder of holiday photos.

The first line is the folder's whole name. Below it come the entries, one to a line, with folders first and then files. Names are in the order that ls uses, so capital letters come before small ones. The two spaces before each name are where marks go. In the figure, two photos have a >.

Names that start with a dot are hidden. Those are files that programs keep for themselves, such as .bashrc, and you seldom want to see them. Folder names have a colour of their own. Names of files that are only a by-product, such as compiled files, are set back in a fainter colour.

The mode line at the bottom says Rimu and how the list is sorted. q leaves the list and returns to the buffer you were in before.

Rimu keeps a list up to date. If another program adds, renames or removes a file in the folder, the line appears or goes within a moment. r reads the folder again at once, and your marks stay.

10.1.1 Commands for opening a folder

ModalNon-modalCommandWhat it does
noneC-x drimuList a folder with rimu, asked for with completion from the folder of the path chosen last in a question for a path, else the current buffer's: its name, then its entries a line each, folders first.
noneC-x 5 drimu-other-frameList a folder with rimu in another frame and work in it, the folder asked for as C-x d asks.
noneC-x C-jrimu-jumpList the directory of the current buffer's file with rimu, point on the file; a buffer with no file lists the directory it stands in.

10.2 Moving about

Moving into a folder shows it in the same list. You do not collect a buffer for every folder you pass through. The keys are the ones you know from chapter 2, with a few more for the places a list has.

ModalNon-modalWhat it does

10.3 What a list shows

At first a list shows only names. You can ask for more, one part at a time. Each key switches its part on and off for the list you are in, and none of them changes a file.

I shows details before each name: the same ones that ls -l gives, which are permissions, the number of links, the owner, the group, the size and the time of the last change. The inode number, which says where the file sits on the disk, comes first. The line under the folder's name then gives how much free space the drive has. Here is a folder with details on.

The permissions say who may read, write and run a file. The first letter is d for a folder and - for a file. The next nine are three groups of three, for the owner, for the owner's group and for everyone else. In each group, r means may read, w may write and x may run or, for a folder, may go into it. So -rw-r--r-- is a file its owner may read and change and everyone else may only read. Rimu shows these but does not change them. If you would rather read them as numbers, as the chmod command does, set *rimu-permissions* to :octal.

H shows the names that start with a dot. s swaps the order between by name and by time, with the most recently changed first. The mode line says which one is in force. S shows a size before each name. For a folder it is the size of everything inside, and it is worked out in the background, so the column fills in after a moment while you carry on. G shows, after each name, when the file was last committed to git and the first line of what the commit said. Chapter 15 describes git.

The standard for each of these is off, with folders first and the order by name. The settings below change the standard for every list.

Try it, with a folder of letters

  1. Open a folder of letters with C-x d. If you have none, make one in a terminal first, or use any folder with several files.
  2. Press I. Details appear. Press I again to hide them.
  3. Press s. The list is now ordered by time, the newest first. Press s again to go back to names.
  4. Press S and wait a moment for the sizes. Find the largest one.
  5. Press H to see the hidden names, and H again to hide them.

*rimu-details* is nil as standard. With t every list opens with the details of I shown:

(setf *rimu-details* t)

*rimu-hidden-columns* leaves parts out, however a list is asked for them. It is a list of the names :inode, :permissions, :links, :owner, :group, :size and :time, which are the details, and :sizes and :git, which are the columns of S and G. It is empty as standard. This leaves out the inode numbers and the groups, so a line of Figure 10.2 starts at the permissions and has no group:

(setf *rimu-hidden-columns* '(:inode :group))

*rimu-dotfiles* is nil, so names that start with a dot stay hidden. Set it to t to start with them shown, as H does.

*rimu-sort* is :name or :time. :name puts capital letters before small ones, as ls does in its plain mode. :time puts the newest change first. For a folder you open to find what changed last:

(setf *rimu-sort* :time)

*rimu-directories-first* is t, so folders, and links that lead to folders, come before the files. With nil everything is in the one order, folders among the files.

*rimu-directory-sizes* and *rimu-git-info* are nil, so the size column and the git column wait until you press S or G. Set either to t and it is there when the list opens. The size of a folder is still worked out in the background.

*rimu-ignored-extensions* is a list of endings. A file whose name ends in one of them is shown faint, in the :list-dim face, so the files you work on stand out from those a program made. Nothing more is done to it: it is still listed, and you can still open, mark, copy and delete it as any other. As standard the endings are .o, .so, .a, .fasl, .elc, .pyc, .pyo, .class, ~ and #: compiled files, backups and the files some editors keep while you type.

An ending is any text the name ends with, not only what follows a dot: ~ sets back notes.org~, and -old would set back report-old. Capital letters count, so .log sets back build.log but not BUILD.LOG; give both to have both. The name must be longer than the ending, so a file called just .o is not set back. Folders and links are never set back, whatever their names end with.

To add your own endings to the standard ones, add them to the list:

(setf *rimu-ignored-extensions*
      (append *rimu-ignored-extensions* '(".log" ".tmp" ".LOG")))

Setting the list itself replaces the standard endings. This sets back only backups and Python's compiled files:

(setf *rimu-ignored-extensions* '("~" ".pyc"))

With nil no name is set back, and every file is shown alike.

*rimu-follow-changes* is t, so a list reads its folder again by itself when a file in it is made, deleted, renamed or finished being written by another program. You see the list change as you watch it. Many changes at once are read as one. Set it to nil and the list stays as it was until you press g r (non-modal: M-x revert-buffer). On a folder that changes without stopping, for example one a program writes to all day, that quiets the list:

(setf *rimu-follow-changes* nil)

*rimu-reuse-lists* is t. When a bookmark takes you to a folder, or you go to a folder across the edge of a project, Tuatara lists it in the list that already belongs to that project, the one used last, and does not open another. If a list shows that folder already, you are taken to it either way. With nil such a folder gets a list of its own each time.

10.4 The preview beside the list

When you rest the cursor on an entry, Tuatara shows it in a window beside the list: the start of a file, or for a folder the list of what is inside. It follows the cursor as you move, so you can look through a folder of notes or photos without opening any of them. On a wide screen the preview stands to the right of the list, and on a narrow one below it. It closes when you leave the list.

A text file shows its text. A picture shows the picture itself in the window (tuatara --gui) and in terminals that can draw pictures, such as kitty. In other terminals you see a line that describes it, such as its kind and size. A PDF shows its first page. T switches between a file's picture and its text. For a PDF the text is the words on all of its pages, which is a quick way to read one. Binary files show in the hex view, as bytes. The preview shows only the first megabyte of a file, so a very large file does not slow the list down.

P turns the preview off and on in the list you are in. If it gets in your way, P is the quickest answer. To turn it off for every list, set *rimu-preview* to nil in your init file (chapter 20).

C-o shows the entry in another window and leaves the cursor in the list. With the preview off it opens a window of its own for the purpose.

10.4.1 Quick edit

Sometimes you only want to fix a word in a file. o turns the preview into the file itself and puts the cursor in it. You can type there as in any buffer. When you are done, press q in NORMAL state, or C-c C-c in any state, and Tuatara asks whether to save what you changed. Then the preview shows the file again and you are back in the list.

Try it, with a folder of letters

  1. In your folder of letters, move to a text file. A window opens beside the list and shows the start of it. If not, press P.
  2. Press P to close the preview, and P again to open it.
  3. Press o. The cursor is now in the file.
  4. Press g e (non-modal: M->) to go to the end, i to type, and add a line such as Thank you. Press C-g.
  5. Press q. Tuatara asks Save letter.txt? (y or n). Press y.
  6. Press k and j (non-modal: C-p, C-n) to move over other entries and watch the preview change.

Two more keys help when you are deciding what a file is. g i shows what the system knows of it: its kind, size, owner, times and checksum. It leaves the file's access time as it was. O hands a copy of a picture, a PDF, a sound or a video to your desktop's own program, after asking, so you can play a video that Tuatara cannot.

10.5 Marks

Marking works as it does in the buffer list. m puts a > on the entry and moves down a line, so pressing it again and again marks a run. A number before it marks that many. u takes the mark off, U takes every mark off, and t turns the marks about, which is the quick way to say "everything but these". d puts a D on an entry instead, which means "delete this one". It does nothing until you press x.

With nothing marked, a command acts on the entry the cursor is on. With entries marked, it acts on them.

A mark stays with its file when you go to another folder. You can mark two photos in one folder, go to another and mark a third, and then copy all three at once. This is useful and also something to watch. Under the folder's name the list says how many entries are marked in other folders, so you are never surprised, and the question that a command asks counts all of them. U takes away every mark in every folder.

K takes the lines of the marked entries out of the list. The files stay as they are, and only the list shows fewer lines. It is a way to cross off what you have dealt with and look at what is left. r brings the lines back.

10.5.1 Filtering a list

A long list is easier to use when it shows only what you want. C-x / s asks for a pattern and keeps the lines that contain it. If you type jpg, only the lines with jpg in them remain, and a line at the top says how many of the entries are shown. A second C-x / s narrows it further. C-x / r takes every filter away. C-x / l lists the filters in force. Marks stay on entries that a filter hides, and a question that counts the entries says how many are hidden, so nothing goes without your knowing.

With the details shown, C-x / f and C-x / h ask for a column first, such as the owner or the size, and then keep or hide the entries whose value in that column matches. Chapter 6 describes the pattern language.

Try it, with holiday photos

  1. Open your folder of holiday photos with C-x d.
  2. Press m on three photos you like. Each gets a >.
  3. Press t. Now every other entry is marked, and the three are not. Press t again to turn them back.
  4. Press U to clear every mark.
  5. Press C-x / s, type jpg and press RET. Only the pictures stay.
  6. Press C-x / r to see the whole folder again.

10.7 Copying, moving and linking

C copies the marked entries, or the one under the cursor. M moves them. The question asks where to, as C-x C-f asks for a file: you type a path, and TAB completes it. If another rimu list is open in the next window, its folder is offered first. That makes it easy to copy from one folder to another that you can see.

A folder goes with everything in it, however many folders are inside. The setting *folder-tree-depth-limit* stops this at a very deep nesting, so that a loop made by mistake cannot run for ever.

M moves only into a folder. To move a file and also give it a new name, use R and a path, or copy it. When you copy a single entry you may type the whole new path, name included.

A large copy runs in the background and the editor stays free. P lights at the front of the mode line while it works. C-x j lists the jobs with how far each has got, and C-x J stops one, taking away a file only half copied.

Nothing is replaced without asking. If a file of that name is already there, Tuatara asks whether to replace it, and the old one goes to the trash first, so you can still get it back. Tuatara also never puts a file on top of itself. Asking to copy a link onto the file it leads to is refused.

Y makes a symbolic link, which is a small file that says where another file is. L makes a hard link, which is a second name for the very same file. A change made through one name shows under the other, and the file stays until both names are gone. A hard link can only be made on the same drive, and never to a folder.

= compares two marked entries and shows what differs, line by line, as git does. With two folders marked, it compares the files that have the same name.

Try it, with holiday photos

  1. In your folder of photos, press m on three photos.
  2. Press M. At the question type the name of a folder, such as Napier/, and press RET. If the folder is not there, Tuatara says so and moves nothing: make it with + and try again.
  3. The three photos leave the list, and Tuatara says Moved 3 files.
  4. Press g f, go to Napier, and press l. They are there.
  5. Put the cursor on one photo and press C. Copy it to your home folder by typing ~/ after clearing the question with C-a C-k.
  6. Press C-x j to see the job list. A small copy has finished already, so the list says there are no jobs.

10.8 Renaming

R renames the entry under the cursor in its place. The question offers the old name, so you can edit it rather than type it all again. A name only: a slash is refused, because moving is M's job. A buffer that visits the file follows it to its new name, and so do the recent files and other lists of the same folder.

To rename many names at once, press C-x C-q. The names of the folder's entries appear as text in a buffer of their own, one to a line. You can now change them with every key that edits text. You can add a word to the start of each line with a many-cursor edit (chapter 5), or run a replacement over all of them (chapter 6). When you press C-c C-c, every line that changed is renamed. C-c C-k leaves the names as they were.

Each line stands for one file. If you delete a line, add one or join two, nothing is renamed, and Tuatara tells you why. Before it renames anything it checks all the names together, so a name used twice, or one that another file already has, is reported and no file is renamed. You can swap two names.

  3. Press I to start INSERT at the beginning of the line. Type Napier- and press C-g.
  4. Press j (non-modal: C-n) and repeat on the next line.
  5. Press C-c C-c. Tuatara says how many were renamed and the list shows the new names.

10.9 Deleting, the trash and wiping

D puts the marked entries, or the one under the cursor, in the trash. This is the same trash your desktop's file manager uses, so a file you delete here can be put back from there too. x does the same for the entries marked with D. Deleting is a two-step in that case: first mark with d, then press x when you are sure.

C-u D deletes for good, and asks twice. Nothing deleted this way can come back. The setting *rimu-delete-to-trash* decides what D does. If you set it to nil, every deletion is for good, after asking twice.

g t lists the trash, as the buffer list lists buffers: a section for your own trash and a section for each drive that has one. The thing that was put in last is at the top, and each line says when it was deleted and where it was. In the list, R puts the marked things back where they were, D deletes them for good and x deletes those marked with D. X empties the whole trash and asks twice. RET opens a thing safely so that you can look at it before you decide. h or q returns to your folder.

A file that you trash on a USB stick goes to the stick's own trash and comes back to where it was. That is why the trash list has a section for each drive. When you pull the stick out, its trash goes with it.

The trash only moves a file. The bytes stay on the drive until the space is used again. If you really want a file's contents gone, g w wipes the marked files: it writes over them and then deletes them. This is slow, and it asks once.

Try it, with some letters

  1. Make two new files in a folder with a: type old-1.txt and RET, then old-2.txt and RET.
  2. Put the cursor on old-1.txt. Press d, which marks it and moves down, then d on the next, so both show D.
  3. Press x and answer y. Both are in the trash.
  4. Press g t. The two are at the top of the trash list.
  5. Put the cursor on old-1.txt and press R. Answer y. It is back.
  6. Press q to return. old-1.txt is in the list again.

Do not press X while you practise. It empties the whole trash, not only what you put there.

10.10 Archives

An archive is one file that holds many files, often squeezed to take less room. A zip of recipes that a friend sent you is an archive. Rimu works with the common kinds: tar archives (plain, or ending .gz, .bz2, .xz or .zst), zip, 7z and rar, ISO disc images and cpio. It tells the kind from the first bytes of the file, so an archive with a wrong name still works. Word, EPUB and Java files are zip archives and open as such.

C-c e shows what an archive holds, in a buffer of its own, without unpacking it. q closes it. It is a way to look inside a zip before you decide whether to unpack it.

Z extracts the archives marked, or the one under the cursor. It asks for a folder, and offers one named after the archive, which it makes if it is not there. Several marked archives go into the one folder you give. If an archive is locked with a password, Tuatara asks for it and types nothing on the screen. The password reaches the unpacking program on its standard input, never on its command line, and a wrong one unpacks nothing.

c goes the other way. It packs the marked entries into one tar archive. The question asks for a name, and its ending says how the archive is squeezed: .tar.gz, .tar.bz2, .tar.xz, .tar.zst, or .tar for none. Another ending is refused. Entries marked in several folders go into one archive and keep their paths below the folder that holds them all.

Unpacking is careful because an archive can hold anything. It happens in the background and shut in a sandbox. Nothing is written outside the folder you chose, whatever names are inside, and a file already there is left as it is. Everything is first unpacked into a new folder of its own and moved into place after, so a half-finished unpack never damages what you had. Unpacking stops before the drive has less than *archive-free-reserve* free, which is a gigabyte unless you change it, so that a small archive that holds a great deal cannot fill the drive. Archives inside an archive stay packed.

Try it, with a zip of recipes

  1. Put a zip file called recipes.zip in a folder, or pack one: mark a few text files and press c, type recipes.tar.gz after the folder offered and press C-j.
  2. Press U to clear the marks, as Z would work on the marked files. Put the cursor on the archive and press C-c e. A list of what it holds opens.
  3. Press q to close it.
  4. Press Z. The question offers a folder named recipes. Press C-j to take it.
  5. Tuatara says Extracted 1 archive. Press l on recipes and see the files.

10.11 Drives and the folder tree

A drive is a disk, a USB stick or a network share that has been attached to the computer, which is called mounting it. Rimu does not mount drives. Your desktop does that when you plug one in, and then you list the drive's folder like any other.

Rimu knows about drives in a few places. A size worked out with S counts what is inside a folder on the same drive only, so a drive attached inside it is not added in. A hard link works only on one drive. The trash of a drive is kept on that drive, as the last section explained.

A folder tree is a folder with its folders and theirs, as deep as they go. S adds up a whole tree. Copying, moving or deleting a folder goes through the entire tree. In a network or a mounted drive that is slow, but the editor stays usable, because the work is done in the background.

10.12 Finding, checking and encrypting

A list can also be made from a search. The commands below make a list of results, and you work on that list as on any other: mark, copy, move, delete.

M-x rimu-find lists the files whose names match a pattern, where * stands for any characters and ? for one. *.pdf finds every PDF below the folder you give. M-x rimu-find-text lists the files whose text holds the words you type. M-x rimu-duplicates lists files that are the same as another, in groups, so you can mark one of each pair for deletion.

The keys that start with : encrypt, decrypt and sign. : e and : d encrypt a marked file into FILE.gpg and decrypt it back. : s signs a file and : v checks a signature.
