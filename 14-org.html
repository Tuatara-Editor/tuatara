Org

Notes, lists, tasks, dates, tables and documents, all in plain text.

Org is a way of writing plain text so that a program can help you with it. A line that begins with a star is a heading. A line that begins with a hyphen is an item of a list. A heading with the word TODO in front is a task. From a handful of marks like these, Tuatara can fold a long note down to its headings, tick off a shopping list, show you what is due this week, add up a column of numbers and turn the whole note into a PDF or a Word document.

The file stays plain text throughout. You can read it in any program, send it to anyone and keep it for decades. Org began in the editor Emacs, and files written there open in Tuatara as they are. Tuatara's Org is its own, written for Tuatara, so nothing in this chapter needs Emacs.

This is a long chapter because Org does a lot. You do not need all of it. The first three sections are enough to keep notes and lists. Read about tasks, dates and the agenda when you want Tuatara to remind you what to do. Read about tables when you have numbers, and about exporting when a note must become a document for someone else.

One reminder about the state keys. i starts INSERT state, and C-g or ESC returns to NORMAL state. Keys that start with C-c, C-x or M- work in both. Where this chapter says "type", do it in INSERT state.

14.1 An Org file

A file whose name ends in .org opens in Org mode, and the mode line says Org. Any other buffer becomes an Org buffer with M-x org-mode. The scratch buffer *org-scratch* of chapter 7 is one already, and is a good place to try things.

Here is a small note as you type it:

#+title: My garden

* Vegetables
The beds by the fence get the most sun.
** Tomatoes
Water *every* morning, /not/ at noon.
** Beans
* Fruit

The first line gives the note a title. Lines that begin with #+ tell Org something about the note and are not part of its text. One star makes a heading of the first level and two stars make a heading under it. There must be a space after the stars. The text below a heading belongs to it, down to the next heading.

Within the text a few marks change how words look, and how they come out in an exported document.

You typeIt means
*bold*Bold
/italic/Italic
_underlined_Underlined
~code~Code, such as a command's name
=verbatim=Text shown exactly as written
[fn:1]A footnote, its text on a line beginning with the same mark

14.1.1 How a note is shown

Tuatara shows an Org file a little tidier than it is written. A heading shows a round sign in place of its last star and the stars before it are hidden. Each line is set in by the level of the heading it is under. None of this changes the file, which still holds the stars at the left edge. This is the indented view. M-x org-indent-mode turns it off for the buffer, so that you see the file as it is, and on again.

If you would rather see the stars always, set *org-startup-indented* to nil in your init file. A single note can say so for itself with the line #+STARTUP: noindent, and #+STARTUP: indent asks for the indented view. *org-bullets* holds the signs that stand for the stars, one for each level, and nil there shows the stars themselves. Lines like #+STARTUP: are read when the file is opened. After you change one, kill the buffer with C-x k and open the file again.

14.2 Headings and folding

Headings are what make a long note manageable. You can hide everything under a heading, move a heading with all that belongs to it, and jump to one by name. A heading together with everything under it, its text and its own headings, is called a subtree.

14.2.1 Folding

Folding hides text without changing it. Press TAB on a heading and everything under it is hidden. Three dots after the heading say there is more. Press TAB again and you see the headings directly under it, each still folded. A third press shows all of it, and a fourth folds it again. The echo area names each step. Figure 14.1 shows the three.

S-TAB does the same for the whole note at once, wherever the cursor is. The first press shows only the headings of the first level, which the echo area calls Overview. The second shows every heading and no text, called Contents. The third shows everything.

A folded part counts as one line. The cursor steps over it and never stands inside it.

A note can say how it wants to open. #+STARTUP: overview near the top opens it folded to its first-level headings, and #+STARTUP: content opens it with every heading and no text. This is worth doing for a long file you open often.

Under a task Org keeps some records of its own, in blocks called drawers that begin with a line such as :LOGBOOK: and end with :END:. They are folded to one line when a file opens, because you seldom want to read them. TAB on a drawer's first line opens it.

14.2.2 New headings

M-RET makes a new heading of the same level, after the subtree the cursor is in. You can press it anywhere under a heading. It leaves you in NORMAL state with the cursor after the new stars, so press i and type the heading. M-S-RET does the same and writes TODO for you, which starts a task.

14.3 Lists and checkboxes

A list is for things that do not each need a heading: what to buy, the steps of a recipe, points to raise at a meeting.

A line that begins with a hyphen and a space is an item. A line that begins with 1. and a space is an item of a numbered list. An item set in further than the one above it is a sub-item of that one. A line written as - term :: what it means is an item of a description list, useful for a short glossary.

- Weed the beds
- Mulch the feijoas
  - Bark, if there is any left
1. Soak the seeds overnight
2. Plant them a finger deep

M-RET on an item makes the next item of the same kind after it. In a numbered list the items after it are numbered again. C-c - changes the bullet of every item in the list to the next kind. The kinds are a hyphen, a plus, a star, 1. and 1), and a list at the left edge skips the star. That is the quick way to turn a plain list into a numbered one. TAB on an item that has sub-items or more lines under it folds it, as on a heading.

14.3.1 Checkboxes

An item that starts with [ ] has a checkbox, something to tick off. You do not have to type all of it. Type the hyphen, a space and [, and Tuatara completes the box and leaves the cursor after it.

C-c C-c on the item's line ticks the box, which then reads [X], or clears it again. In NORMAL state RET on the line goes round three states: empty, [-] for half done, and ticked.

Put [/] at the end of the heading above the list, or at the end of an item that has sub-items, and Org counts for you. It shows how many boxes are ticked out of how many there are, such as [2/5], and keeps the count current as you tick. [%] shows a percentage instead.

When you tick a box, Tuatara notes the time in a small drawer under the item. That lets the agenda show later what you finished on which day. If you do not want these notes, set *org-log-checkboxes* to nil.

14.4 Tasks

A checkbox is enough for a shopping list. A task is for work that takes longer, that may have to wait for someone, or that has a date. A task is a heading with a keyword after its stars:

* TODO Paint the fence
* WAIT Quote from the plumber
* DONE Ring the council

Four keywords come as standard. TODO is for something still to do. WAIT is for something that is waiting on a person or an event. DONE is for something finished, and CANCELLED for something you gave up. The first two count as open and the last two as closed.

C-c C-t gives the heading the next keyword: none, TODO, WAIT, DONE and none again. S-<right> and S-<left> go forward and back through the same round. In NORMAL state RET on a task's line also moves it to the next keyword, and never leaves it without one. CANCELLED is left out of the round so that you do not cancel something by pressing a key once too often. C-c C-x C cancels the task the cursor is in.

When a task becomes DONE, Tuatara writes a line under it that says when:

* DONE Paint the fence
  CLOSED: [2026-10-13 Tue 10:00]

The agenda can list what you closed on each day from these lines. Taking DONE away again removes the line. Set *org-log-done* to nil if you want nothing written.

14.4.1 Tasks with parts

A task can have smaller tasks under it, or a list of checkboxes. Put [/] at the end of its heading and it counts them. When the last one is done, the task becomes DONE by itself, and it becomes TODO again if you reopen one. While a part is still open, RET passes over the closed keywords, so a task is not marked done by accident with work left under it. C-c C-t still lets you close it if you mean to.

14.4.2 Notes on a task

C-c C-z asks for a note and files it under the task with the date and time. Use it for what you would otherwise forget: "rang twice, no answer", "the paint is in the shed". Notes go into the task's :LOGBOOK: drawer, the newest first, with the other records Tuatara keeps of the task. Open the drawer with TAB on its first line.

14.4.3 Keywords of your own

A note can name its own keywords on a line near the top. Those before the bar are open and those after it are closed:

#+TODO: TODO NEXT WAIT | DONE CANCELLED

To change the keywords for every file that has no such line, set *org-standard-todo-keywords* in your init file. *org-todo-keyword-faces* gives a keyword a colour of its own.

14.4.4 Priorities

A task can carry a priority, written by hand after its keyword as [#A], [#B] or [#C]. It is shown in its own colour, here and in the agenda, so that the important tasks stand out.

14.5 Tags

A tag is a word at the end of a heading, between colons, that says what the heading is about:

Tags cut across the outline. A note about the house and a note about work can both hold headings tagged phone, and the agenda can list every one of them when you sit down to make calls. A heading also has the tags of the headings above it, so tagging a whole project once is enough.

C-c C-q sets the tags of the heading the cursor is under. It offers the tags the heading has. Type the words with spaces between them, or nothing to remove them all. You can also type tags by hand.

As standard the tags sit one space after the heading's text. If you like them lined up at the right, set *org-tags-column* to a negative number, such as -77 for tags that end at column 77. 14.6 Dates and scheduling

A date in an Org file is written in angle brackets, as <2026-12-24 Thu>, or with a time, as <2026-12-24 Thu 14:00>. You never have to type one out. The commands of this section ask for a date and write it for you, weekday and all.

There are three ways to put a date on something, and they mean different things.

Scheduling and deadlines are for tasks. They are written on a line of their own right under the heading, beginning SCHEDULED: or DEADLINE:. A scheduled task that you do not finish is carried forward in the agenda day after day until you do. A deadline shows up in the agenda some days ahead, 14 unless you change *org-deadline-warning-days*, so that it does not take you by surprise.

A date in the text is for an event such as a flight, a birthday or a meeting. C-c . puts one where the cursor is. The agenda shows it on its day and nowhere else.

C-c ! writes a date in square brackets, as [2026-12-24 Thu]. Such a date is only a record. The agenda leaves it out. Use it to note when something happened.

You can point. Before you have typed anything, l and h move a day forward and back and j and k move a week. RET writes the day at the prompt, and a second RET accepts it. Between the two you can add a time, such as 14:00.

14.7 The agenda

Dates scattered over a dozen files are of little use unless something gathers them. The agenda does that. It reads your agenda files, finds every task and every date in them, and shows them in one list in the order of the calendar. You look at it in the morning to see what the day holds.

14.7.1 Telling Tuatara which files to read

The agenda reads the files named in *org-agenda-files*. As it comes, that is the one file ~/org/agenda.org. Set it in your init file to the files or folders where you keep tasks. A folder stands for every .org file in it.

(setf *org-agenda-files* '("~/org/" "~/holiday.org"))

14.7.2 Opening it

C-x a a asks which view you want and waits for one more key.

KeyView
aThe week, day by day
tEvery task that is still open, dated or not, with unticked checkboxes
mThe headings that match tags you type, such as phone or work+urgent
uThe open tasks that have no tag
cThe entries whose dates look wrong, each with the reason

C-x a w, C-x a m and C-x a y open the week, the month or the year without asking. Figure 14.2 shows a week.

Each line starts with the name of the file the entry is in, then its time or all day, then what kind of line it is. Scheduled: is a task planned for that day. Deadline: is a task due that day, and In 3 d.: on today is the early warning of a deadline three days off. Event: is a date in the text. The tags are at the right. In the figure, cleaning the gutters appears twice: on Friday when it is due and on today as a warning.

On today the agenda also draws a time grid when something has a time, with a line for the hour it is now, so that you see what is still ahead.

14.7.3 Moving about

j and k move from line to line. l shows the next week and h the one before. g h comes back to today. D, w, m and Y change the span to a day, a week, a month or a year, and g l returns to the view you had before. RET opens the entry on the line in its file, and TAB shows it in another window while you stay in the agenda. c opens the calendar on the line's day, and a in the calendar shows the agenda of the week of the day the cursor is on. q closes the agenda.

The agenda keeps itself current. It is drawn again when one of its files changes, every ten minutes and just after midnight. r draws it again at once.

You do not have to open a file to deal with a task. The keys below act on the entry of the line the cursor is on, and change it in its file.

L turns on log mode. The agenda then also lists, on each day, the tasks you closed and the time you clocked. It is a pleasant way to see on a Friday what the week went on.

i takes down something new for the day the cursor is on, with capture, which is described below.

14.10 Clocking

The clock records how long you spend on a task. It is for anyone who bills by the hour, and for anyone curious where a day went.

C-c C-x C-i starts the clock on the task the cursor is under. A line beginning CLOCK: is written in the task's :LOGBOOK: drawer with the time you started. While the clock runs, the mode line of every window shows the time so far and the task's name, so you cannot forget it. Starting the clock on another task stops the first.

C-x a o stops the clock from any buffer. The line is finished with the time you stopped and how long that was:

CLOCK: [2026-10-13 Tue 10:00]--[2026-10-13 Tue 10:45] =>  0:45

C-x a j takes you to the task that is being clocked, from wherever you are. C-c C-x C-q stops the clock and removes its line, for when you started it by mistake. In the agenda, I and O start and stop the clock on the line's entry.

If you leave Tuatara while the clock runs, it asks whether to stop it. If you say no, the clock is found again at the next start and goes on counting.

To add the time up, run M-x org-clock-report. It writes a table of the time spent on each heading, with a total, for the subtree the cursor is in or for the whole file when the cursor is above the first heading. At the end of a row TAB starts a new row. So filling in a table is typing a field, TAB, a field, TAB. Numbers are set to the right of their column and words to the left.

14.11.2 Formulas

A table can do sums. Its formulas are written on a line right under it that begins #+TBLFM:. A formula names a place in the table, an equals sign, and how to work the value out.

| Crop     | Kg | Price | Value |
|----------+----+-------+-------|
| Tomatoes | 12 |  4.50 |   54. |
| Beans    |  3 |     6 |    18 |
| Total    |    |       |   72. |
#+TBLFM: $4=$2*$3::@>$4=vsum(@2..@-1)

There are two formulas here, with :: between them. The first says that column four is column two times column three, in every row below the rule. The second says that the last row of column four is the sum of the rows above it.

In a formulaMeans
$2The second column
@3The third row, with rules not counted
@>, $>The last row, the last column
@-1The row above
@2..@-1A range, here from the second row to the row above
vsum, vmeanThe sum and the mean of a range
vmax, vmin, vcountThe largest, the smallest, and how many
;%.2f after the formulaWrite the answer with two decimals

The numbers do not change by themselves when you change a field. Press C-c * anywhere in the table to work the formulas out again, or C-c C-c on the #+TBLFM: line.

You do not have to write that line by hand. C-c = asks for the formula of the column the cursor is in and adds it to the line for you. With C-u first, it asks for a formula for the one field.

A field that cannot be worked out shows #ERROR. Usually a field the formula reads holds a word where a number should be, or the formula names a column the table does not have.

Try it, with a small budget

  1. Open ~/budget.org with C-x C-f. Press i and type |Item|Cost, then press TAB. The line becomes a tidy row and a second row starts.
  2. Type Rent, TAB, 450, TAB, Food, TAB, 180, TAB, Power, TAB, 95, TAB, Total. Press C-g.
  3. Move to the row Item and press C-c -. A rule is drawn under it.
  4. Move to the row Total and press o to open a line under the table. Type #+TBLFM: @>$2=vsum(@2..@-1) and press C-g.
  5. Press C-c C-c on that line. The field beside Total shows 725.
  6. Move to the 180 of the Food row and change it to 200. Press C-c *. The total becomes 745. Save with C-x C-s.

A link leads from one place to another: to a heading further down, to another file, to a web page. It is written in double square brackets, with the place it leads to first and the words to show second:

14.12.1 Making and following links

You seldom write a link by hand. The usual way has two steps. Go to the place you want to link to and press C-x a l, which remembers a link to it. Then go to where the link should be and press C-c C-l. It offers the links you have remembered, the latest first, and then asks for the words to show. If you have text selected, that text becomes the words. With C-u first, C-c C-l asks for a file to link to. On a link that is already there, it lets you change it.

C-x a l works in any file. Under an Org heading it remembers the heading. In a file that is not Org it remembers the line.

To follow a link, press RET on it in NORMAL state, or C-c C-o in either state. A link to a web page or a mail address opens in your desktop's program, and Tuatara asks before it does that. If you would rather RET did not follow links, set *org-return-follows-link* to nil.

Two more commands write a link that stands for a set of notes, the files with formatted names of chapter 9 whose names match a pattern. Following such a link lists the matching notes so that you can open one. M-x match-formatted-files-link writes Tuatara's own kind, and M-x match-denote-files-link writes the kind that the Emacs package Denote understands as well.

14.13 Blocks and code

A block is a stretch of text set apart between a line that begins #+begin_ and one that begins #+end_. The word after the underscore says what kind of block it is.

BlockIs for
srcCode, coloured as its language is
exampleText shown exactly as typed, such as what a program printed

You do not type the two lines yourself. Type <s and press TAB, and a source block is written around the cursor with a list of languages to pick from. <e, <q, <v and <c do the same for the other four. These are snippets, which chapter 13 describes.

#+begin_src shell
echo "Water the beds at dawn"
#+end_src

The code in a source block is coloured as it would be in a file of that language. Org's name for a language is sometimes different from Tuatara's. *org-src-languages* maps one to the other, and you can add your own.

14.13.1 Writing the code out to files

A note can hold the code of a program or of your configuration, with the explanation around it, and write the code out to the files that need it. Give a source block the words :tangle and a file name on its first line:

#+begin_src shell :tangle water.sh
echo "Water the beds at dawn"
#+end_src

C-c C-v t then writes every such block to its file. Blocks that name the same file go into it in order. Before anything is written, Tuatara lists the files and says which are new and which would change, and asks. This suits settings files well: the note says why each setting is there, and the file the program reads is made from it.

14.13.2 A table of contents

Tag a heading TOC and Tuatara keeps a table of contents under it, a list of links to the note's headings. It is made again each time you save. The tag can say more: TOC_3 lists headings three levels deep. M-x toc-org-insert-toc makes it at any other time.

Apart from the clock table, the kinds list or include your files with formatted names: links to those that match a pattern, links to the notes that link to this one, or the text of the matching files themselves. C-c C-c on a block's first line, or C-c C-x C-u anywhere in it, writes it again from how things stand now. M-x org-update-all-dblocks does that for every such block in the buffer.

14.14 Exporting

A note is for you. A letter, a report or a set of minutes is for someone else, who wants a PDF or a Word document. Exporting makes one from the note. The headings become numbered sections, the lists become lists, the tables become tables, and the marks for bold and italic become bold and italic.

Tuatara makes a PDF by way of LaTeX, a typesetting system that produces handsome pages. You do not need to know LaTeX, but it must be installed: the program xelatex or lualatex, from the collection called TeX Live. M-x check-health tells you whether Tuatara found one. A Word document needs nothing else installed.

The export commands have no keys. Run them with M-x. The command you ran last is offered first there, so exporting again after a change is M-x RET.

14.14.1 What goes at the top of the note

A few lines at the top say what the document is.

#+title: The fence between our sections
#+author: Aroha Ngata
#+date: 14 October 2026
#+options: toc:nil num:nil

The title, author and date are printed at the head of the document. Without an #+author: line, the name in *user-full-name* is used. The #+options: line here leaves out the table of contents and the numbers before headings, which suits a letter. Leave the line out and a report gets both. A heading tagged noexport is left out of the document with everything under it, which is handy for notes to yourself.

14.14.2 Making a PDF

M-x org-export-latex-pdf-enhanced-buffer makes the PDF and shows it beside your note. The work is done in the background, so you can go on writing. The mode line shows that a job is running and the echo area says when the file is written and how long it took. The PDF is put beside the note with the same name, letter.pdf for letter.org. If you change the note and export again, the PDF on the screen is read again at the page you were on.

Two more commands do the same and differ only in what happens afterwards. M-x org-export-latex-pdf-enhanced makes the PDF and shows nothing. M-x org-export-latex-pdf-enhanced-xdg opens it in your desktop's PDF reader.

The export takes the note as the buffer has it, saved or not. To export only part of a note, select the lines first.

If LaTeX fails, the echo area names the line of your note where it went wrong, and a buffer called *LaTeX errors* lists each error. RET on one shows that line of the note. An export is a background job like any other, so chapter 11 applies to it. C-x j lists what is running and C-x J stops it.

14.14.3 Making a Word document

M-x org-export-docx writes the note as a Word document beside it, and M-x org-export-docx-xdg also opens it in your desktop's word processor. The document is laid out as the enhanced PDF is, with the same numbering and the same tables, so you can send whichever the other person prefers.

Try it, with a letter

  1. Open ~/letter.org with C-x C-f. Press i and type the four lines shown under "What goes at the top of the note", with your own name.

  2. Leave an empty line and type the letter:

       Dear Mr Tane,

   Thank you for offering to share the cost of the new fence. The quote
   from Motueka Fencing is *$1,840* for the whole length.

   - Posts and rails: $1,100
   - Labour: $740

   Yours sincerely,

   Aroha Ngata
  3. Press C-g and save with C-x C-s.
  4. Press M-x, type org-export-latex-pdf-enhanced-buffer and press RET. After a few seconds the letter is shown as a PDF at the right, with the title at the top, the sum in bold and the two costs as a list. On a narrow screen the PDF takes the whole window instead. Press C-x k to close it and return to the note before the next step.
  5. Press M-x, type org-export-docx and press RET. The echo area says that ~/letter.docx was written.

The commands above all have "enhanced" in their name or, for Word, behave that way. There is a second, plainer family without the word.

14.14.5 Layout in plain words

In the enhanced export a wide table is made to fit. Columns of sentences wrap, numbers go to the right, and the header row is repeated when the table runs on to another page. Most tables need nothing from you.

When you do want to change how something is set, you say so in a drawer called :EXPORT:, in words. Put it right under a heading to affect the heading and all under it, or just above a table, list, block or picture to affect that.

* Costs
:EXPORT:
new page: before
spacing: 1.5
:END:

This starts the section on a new page and sets its lines one and a half apart. The drawer itself is never printed. You do not need to remember the settings. M-x org-insert-export-drawer writes a drawer for whatever the cursor is on, holding every setting that fits it, each set to auto for you to change. M-x describe-export-settings explains them all, with examples. A word in a drawer that is not a setting is shown in the colour of an error as you type it.

14.14.6 Your own look

A template gives a document its look: the fonts, the margins, a header with a logo. A note chooses one with a line at the top, #+template: and the template's name. Templates are kept in your configuration folder.

The simplest start is M-x export-latex-template-copy. It copies one of the built-in templates to your folder and opens it for you to change. If someone gives you a Word or LaTeX document and asks for reports that look like it, M-x export-template-from-docx and M-x export-template-from-latex make a template from that document.

A note template is the other half: the lines a new note of some kind starts with, such as the #+template: line and the headings every report has. C-x i reads one into the buffer.

The fonts of the enhanced export are *latex-main-font* for the text, *latex-sans-font* and *latex-mono-font*. Each is the name of a font family installed on your machine. Left alone, Tuatara picks an installed font for each.

14.14.7 Hiding names

Sometimes a document must go out with a name blacked out. Select the name, or put the cursor on it, press C-c m and choose R. The name is wrapped in a mark and shown in its own colour. In the PDF and in the Word document a black box stands where the name was, and the name is nowhere in the file. C-c M takes the mark away again.

A box is of little use if the same name stands in plain text two pages later. M-x export-check-redactions looks for every hidden text that also appears unhidden and lists the places. The export runs the same check and asks before it goes on. Only the enhanced export hides text. The plain export refuses a note that asks for it.

14.14.8 Notes from other people

An exported note can pull in other files: pictures it shows and setup files it names. A note that someone sent you could name files of yours that way. So the export takes files only from the note's own folder and the folders in it, and says what it left out. *export-trusted-folders* names further folders you allow. Chapter 12 has more on files you do not trust.

14.15 Where to go from here

Org rewards starting small. Keep one file of notes and fold it. Add a list with checkboxes when you next go shopping. When the tasks pile up, give them dates and open the agenda each morning. The rest of this chapter will still be here when you need a table or a PDF.

Many people keep their Org files under version control, so that every change to their notes is kept and can be taken back. That is the subject of the next chapter.
