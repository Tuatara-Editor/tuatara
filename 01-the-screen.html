The screen

What Tuatara shows you, and the name of each part.

When Tuatara starts, its screen is divided into a few parts. Each part has a name, and the rest of this manual uses those names. This chapter goes through them from the large ones to the small ones. For each part it lists the keys that act on it and the settings that change how it looks.

1.1 Keys and names

Most commands have a key. A key written as C-x means hold down the Control key and press x. A key written as M-x means hold down Alt (called Meta in older manuals) and press x. On a terminal where Alt does not reach the program, press Escape, let go, then press x. S- stands for Shift.

Several keys in a row, as in C-x C-f, are pressed one after the other. You may keep Control held down through the whole sequence. A few keys have names instead of letters: RET is Return (Enter), TAB is Tab, SPC is the space bar, DEL is the Backspace key and ESC is Escape.

Every command also has a name, such as find-file. You can run any command by its name. Press M-x, type a few letters of the name, and press RET. The list of choices that appears shows the keys of each command beside it. A command that has no key can only be run this way, and the tables in this manual say "none" for it.

A setting is a name that starts and ends with a star, such as *mode-line-tuatara*. Settings go in your init file, the file Tuatara reads when it starts, as in (setf *mode-line-tuatara* nil). Each table of settings in this chapter gives the standard value, the one Tuatara has until you change it.

Tuatara is a modal editor, which means a key can do different things depending on a state the editor is in. There are two states you will meet first. In NORMAL state, the letter keys are commands: i starts INSERT state. In INSERT state, the letter keys write text. C-g or ESC takes you back to NORMAL state. The mode line, described below, always tells you which state you are in.

1.2 The parts of the screen

Figure 1.1 shows the whole editor with two windows and a question open, and names each part.

The frame is everything Tuatara draws. In a window of its own it is that window, and in a terminal it is the terminal's screen.

A window is a part of the frame that shows one piece of text. Each window has a mode line under it, a row that describes what the window shows.

The echo area is the last row of the frame. Tuatara says short things there, such as Wrote /home/you/list.txt.

The minibuffer is the same row when Tuatara asks you a question. The question is called the prompt, and what you type after it is your answer.

The panel is a few rows above the last row. It lists choices while a question is open, and it lists the keys you can press next after a key such as C-x. It is only there when it has something to say.

The cursor is the mark that shows where typed text goes. Other editors call that place the point, and Tuatara's help uses the word too.

The gutter is the narrow strip at the left edge of a window. It can hold line numbers.

1.3 Windows and buffers

A buffer is a piece of text Tuatara holds in memory. When you open a file, Tuatara reads it into a buffer. Your changes go to the buffer, and the file on disk changes only when you save with C-x C-s. Not every buffer has a file. *Messages*, the log of what the echo area said, is a buffer. So is the list of files you get from find-file. Buffers that Tuatara makes itself have their names between stars.

A window is a view of one buffer. Two windows may show the same buffer, each at its own place, or different buffers. Closing a window never closes its buffer, and killing a buffer closes only the windows that were made for it.

Tuatara puts new windows where you would expect. A help buffer opens in another window. The *Messages* log opens across the bottom, 30% of the height, and takes the cursor so that you can read it; q closes it. A window that already holds a buffer is never split into pieces smaller than *window-min-height* rows or *window-min-width* columns.

Try it, with a shopping list and a recipe

  1. Press C-x C-f, type ~/shopping.txt and press RET. The file does not exist yet, so Tuatara makes an empty buffer with that name.
  2. Press i to start INSERT state. Type eggs, RET, bread, RET, milk. Press C-g to go back to NORMAL state, then C-x C-s to save.
  3. Press C-x 3. The window splits in two, side by side, and both show the shopping list. The left window keeps the cursor.
  4. Press C-x o to move to the right window. Press C-x C-f, type ~/pancakes.txt, press RET, then press i and type a recipe.
  5. Press C-x o to go back to the left window. Press C-x 1. The left window fills the frame again. The pancake buffer is still there: press C-x b, type pan and press RET to bring it back.

1.4 Frames, windows of their own and terminals

Tuatara runs in two ways. Typed as tuatara, it runs in the terminal you started it from. Typed as tuatara --gui, it opens a window of its own on the desktop, drawn with GTK, the toolkit most Linux desktops use. Both have the same keys, the same commands and the same parts. The window of its own has things a terminal does not, such as pictures in every case, a font you can change and ligatures where the font has them.

A frame is one such screen. You can have several frames. In a window of its own each frame is a separate desktop window. A terminal has only one screen, so its frames take turns: the one you work in is shown, and the others wait. When frames take turns, the mode line starts the buffer's name with the frame's name, F1, F2 and so on. Every frame has its own windows and its own echo area. They all show the same buffers, so a change you make in one frame is in the other at once.

Tuatara can also run in the background as a daemon, started with tuatara --daemon, and be reached with tuatara --client, each client with frames of its own. The sign D in the mode line, described below, says that the editor you are in runs as a daemon.

Try it, with two frames

  1. In a terminal, start Tuatara with tuatara ~/shopping.txt.
  2. Press C-x 5 2. A second frame opens showing the same file. In a terminal the new frame replaces the first on the screen, and the mode line now starts the buffer's name with F2.
  3. Press C-x 5 o to go to the other frame, and back again with the same keys. The mode line says F1 in the first.
  4. Press C-x 5 0 in the second frame to close it. Closing the last frame is refused. Quit with C-x C-c.

1.5 The mode line

The mode line is the bar under every window. It says what the window shows and in what state. The mode line of the window you are working in is drawn brighter than the others. Here is a typical one.

Read left to right, the parts are these.

  1. The modal state, in square brackets after the word TUATARA.
  2. Up to four signs, P, U, S and D, always in the same place.
  3. The marker that says whether the buffer is saved, [-], [*] or [%].
  4. Words about the buffer itself, such as Safe or Narrow, when they apply.
  5. The buffer's name.
  6. The line and the column of the cursor.
  7. The name of the buffer's major mode, when it has one.
  8. Anything more the buffer has to say, such as CRLF or Page 3 of 10.
  9. The folder the buffer lives in, at the right end.

Only the parts that apply are shown, and a mode line that is too narrow cuts the buffer's name in the middle, with a mark for what is left out.

1.5.1 The modal state

The first part tells you what a key will do. TUATARA[N] is NORMAL state, TUATARA[I] is INSERT state. TUATARA[S] is a support buffer, one that holds a list, help or the *Messages* log. There you can read, move and select but not type. TUATARA[E] is a buffer that holds no modal keys, such as the Lisp prompt (IELM). With *modal-editing* set to nil there is no modal part at all.

With *mode-line-tuatara* set to nil the word TUATARA is left out and only [N] remains. C-x T t switches it while Tuatara runs.

1.5.2 The signs P, U, S and D

Four letters stand before the saved marker, side by side. Each is faint when nothing is going on and bright, in the warning colour, while its work goes on. They never move, so nothing after them jumps when one lights up. A sign stays lit for half a second after its work ends, so that a short job can be seen.

SignSettingWhat it says
P*processing-indicator*Processing. A job is running for this buffer, or waits its turn. Jobs are things done in the background, such as a search through a large file, a sort or a save. C-x j lists them.
U*indexing-indicator*Update. A folder you asked Tuatara to keep read in memory is being read.
S*searching-indicator*Search. A search runs over such a folder.
D*daemon-indicator*Daemon. This editor runs in the background as a daemon.

U and S only appear when *indexed-directories* names some folder, and P and D always appear. Set any of the four settings to nil to hide that sign, or to another piece of text, such as "indexing" or an icon from a font that has one, to show that instead.

Next comes the marker for the buffer's state.

Just before the buffer's name, Tuatara may add a word that is lit up in a colour of its own.

1.5.5 The name, the line and the column

The buffer's name follows. When it is long, it is cut in the middle and a mark stands for what is left out, down to 12 columns. *mode-line-name-limit* sets a shorter limit.

After the name comes L and the line number, then C and the column, which counts from 0. A number above 999 has commas, as in L100,000,001. When Tuatara is still counting the lines of a very large file you see L... instead, and the number appears when the count is done. The same holds for a column on a line too long to measure at once.

After them, if the buffer has a major mode, comes its name, such as Org or Terminal. A major mode is the set of habits Tuatara gives a buffer according to what it holds: how it colours text, which keys it adds, and so on.

1.6 The echo area and the messages log

The echo area is the last row of the frame. Tuatara writes a short message there after most things you do, such as Wrote /home/you/letter.txt, and the message stays until the next key you press does something. It also shows the keys of a long sequence while you are typing it, and asks questions that one key answers, such as yes or no.

Every message is also kept in the *Messages* buffer. A message said twice in a row is written once with a count, as in Saved [3 times]. The buffer is read-only, and it holds the last 1000 lines. Messages said while a password or other secret was at hand are shown but not kept.

C-h e opens the log across the bottom of the frame, 30% of the height, with the cursor in it. It is a read-only buffer, so q closes it. The log is the place to look when a message went by too fast.

Try it, with a message gone by

  1. Press C-x C-f, open ~/shopping.txt, press i, type tea and press C-g. Then press C-x C-s. The echo area says that the file was written (on a file with no change it says that no changes need to be saved). The message disappears when you press the next key.
  2. Press C-h e. The log opens at the bottom with the message in its last line. Press q to close it.
  3. Press C-h N to read the notifications Tuatara or its packages have given this session, for example when an agenda entry's time came.

1.7 The minibuffer and its prompt

When a command needs something from you, a file name, a word to search for, a yes or no, it asks in the last row of the frame. That row is then called the minibuffer. The words that ask are the prompt, such as Find file:, and your answer follows it. The prompt is drawn in bold. A frame that has a question open keeps its window text where it was, and its cursor is drawn as an outline there while you type in the row below.

Press RET to give the answer, or C-g or ESC to give up. Before the prompt Tuatara may show a count, such as 3/12, which means the third of twelve choices. A search shows which match the cursor is at and how many there are. */0 means nothing matches but what you typed can be taken, and !/0 means it cannot.

You edit the answer with keys much like the ones in a text buffer. These keys work only while a question is open, so M-x does not list their commands.

1.8 The choices panel

When a question has a list of answers, Tuatara shows them in the panel above the last row, and narrows them as you type. Completing means finishing your answer from that list. Type any part of a name. Several words may be typed, and a choice has to match all of them, in any order. The letters that matched are coloured, one colour for each word.

The selected choice is drawn reversed. C-n or <down> select the next one and C-p or <up> the one before. Above the first one is the line you typed, when what you typed can be taken as it is. TAB puts the selected choice into the answer. For a file name it replaces the part after the last slash, and for a folder it goes into the folder, so that you can walk down a path with TAB. RET gives the selected choice, and C-j gives what you typed.

At most 10 rows are used for the panel, the prompt row included. When there are more choices, M-t makes the panel as tall as the frame allows, and again as usual. A choice may have a note beside it, such as the keys of a command, the mode of a buffer or the permissions of a file. A title with a line beside it begins a group, such as the folder that the files under it are in.

Try it, with a folder of notes

  1. Press C-x C-f. Tuatara starts where you chose last and lists what is there.
  2. Type ~/ and look at the panel. Each choice is a file or a folder.
  3. Type a few letters of a file's name. The list shrinks.
  4. Press C-n twice and C-p once. The marked line moves.
  5. Press TAB. The name is put into the answer. If it was a folder, its contents are listed.
  6. Press M-t. The panel grows. Press it again to shrink it.
  7. Press C-g to give up.

1.9 Key hints

Press C-x and wait. The panel lists every key that can follow, with the name of its command, so you do not have to remember them. Names that start with a plus sign, such as +rectangles and registers, are further prefixes, and pressing their key opens another list. A key whose command cannot run in this buffer is dimmed, and pressing it says why. C-h right after a prefix key lists every key under it in a buffer of its own. C-g closes the hints.

The hints take as many rows as the frame has room for, and the echo area stays under them. If they do not all fit, the last row ends in ... C-h lists all.

Try it, with the keys under C-x

  1. Press C-x and wait a moment. The panel appears with keys such as C-f, C-s and 5.
  2. Press 5. The panel changes to the keys under C-x 5, the ones for frames.
  3. Press C-g. The hints close and nothing was run.
  4. Press C-x and then C-h. A buffer lists all the keys under C-x.

1.10 The cursor, the gutter and header lines

The cursor is drawn as a block as standard. A bar or an underline can be chosen, and each modal state may have its own shape and colour, so that you see at once whether you are in NORMAL or INSERT state. In a window that does not get the typing the cursor is drawn as an outline in a window of its own and as an underline in a terminal.

The gutter is on the left edge of a window. It is empty as standard. Line numbers appear in it when you ask: M-x toggle-line-numbers goes through none, absolute and relative, where relative numbers show how many lines away each line is. Where a long line wraps, the gutter shows a mark beside the extra rows.

Tuatara has no tab bar. Buffers are reached by name (C-x b) or from the list (C-x C-b). A window can have a header line at its top. A file of records, such as a CSV, can keep its first row, the header, at the top of the window while the rest scrolls under it.
