Commands, keys and help

Running a command by its name, the keys that start longer keys, and the help that Tuatara keeps for itself.

Everything Tuatara does is a command. Moving down a line is a command, so is saving a file, and so is sorting a list. Most commands have a key, but many do not, and nobody remembers all of them. This chapter is about the ways of finding and running a command without knowing its key. It starts with M-x, which runs any command by name, and with the count that you can give to a command. It then explains the prefix keys, the keys that start a longer key, and the key hints that show you what can follow. The longest part is about help: how to ask what a key does, what a command does, what a setting is and where to look when you do not know the name. The end of the chapter has the page that introduces Tuatara, the check of what your system has, and a short look at running Lisp in the editor.

Before you start, one reminder about the state keys. i starts INSERT state, and C-g or ESC returns to NORMAL state. The keys in this chapter that start with C-x, C-h or M-x work in both states, and the others are pressed in NORMAL state.

8.1 Running a command by name

M-x asks for the name of a command in the minibuffer, the row at the bottom of the screen where Tuatara asks its questions, and runs the command you choose. It is the way to run anything that has no key, and the way to run something you only need once in a while. You use it when you know what you want done but not which key does it.

You do not type the whole name. As you type, Tuatara lists the commands that match, and each one shows its keys and the first line of what it does. The words you type may be in any order, so lines sort finds sort-lines. The first letters of the words also match, so sbke finds save-buffers-kill-editor. C-n and C-p move down and up the list, TAB puts the chosen name into what you typed, and RET runs it. C-g gives up and nothing runs. The commands you ran lately come first, so a command you use often needs only a few letters.

Figure 8.1 shows the minibuffer after typing sort lines with some text selected.

A command that needs something from you asks for it after you press RET, in the same row. sort-lines, for example, works on the lines you have selected, and flush-lines asks for the text to look for. A command made for one kind of buffer says so when you run it in another, and tells you where it works.

Try it, to find a command for sorting lines

  1. Press C-x C-f, type ~/shopping.txt and press RET. Press i and type milk, RET, eggs, RET, bread, RET, apples. Press C-g.
  2. Press M-< (modal: g g) to go to the top. Press V to select the first line, then J J J to take in the other three.
  3. Press M-x and type sort lines. The list shows sort-lines first, with its first line of help beside it. Press RET.

8.1.1 The count before M-x

A count given before M-x goes to the command you choose. C-u 3 M-x upcase-word makes the next three words capital letters. The next section says how a count is typed.

8.2 Counts

A count tells a command how many times to do its work, or gives it a number to work with. You type C-u, then the number, then the key or command. In NORMAL state C-u 5 j moves five lines down. C-u alone means 4 and C-u C-u means 16, and a minus sign makes the count negative, which turns many commands around. Chapter 2 shows counts with moves, and the other chapters name what a count does for their commands, such as how many cursors to add or how many lines to kill. The count is always taken by the command that follows it.

. (non-modal: C-x z) runs the last command again, with the count it had. It is the quickest way to do the same small thing three times. After C-u 4 j, pressing . goes four more lines down. A command started with M-x is repeated as well, with its count. Without the modal layer, each z pressed after C-x z repeats once more, until another key is pressed.

Inside a question, C-u does something else. In the minibuffer it clears what you typed, and leaves the question as it is. That is useful when you started a long name and want to begin again.

8.3 Giving up

C-g is the key to press when you are unsure. It closes a question, closes a list of choices, closes the key hints, drops a selection and leaves INSERT state. Whatever you were in the middle of is abandoned, and nothing is run.

ESC is a key of its own as standard. It does what it is bound to, and where it is bound to nothing it does what C-g does. It closes a question typed in the minibuffer and leaves INSERT state, but it does not end a question that is answered with one key. If you would rather have ESC do everything that C-g does, set *escape-quits* to t in your init file, the file described in chapter 20.

8.4 Prefix keys

Most of the keys you press are one key. Longer keys are made by pressing a prefix first and then another key, as in C-x C-f. A prefix key gathers a family of commands under one key, so that a small number of keys at the top leads to many commands. Tuatara uses four of them in particular ways.

C-x is the family of global commands. Its keys are the same in every buffer and in both states: C-x C-f finds a file, C-x C-s saves it, C-x b goes to another buffer, C-x C-b lists them. Under it are smaller families with a name: C-x w for windows, C-x r for rectangles and registers, C-x m for bookmarks, C-x p for projects, C-x T for things you switch on and off. The chapter for each subject says which keys it uses.

C-c is the family of the buffer you are in. Its keys differ from mode to mode. In a list of buffers, C-c shows what the list can do. In an Org note it shows what Org can do, and in a PDF it shows how to turn a page. It is the one prefix to try when you wonder what a particular buffer offers. In the terminal that Tuatara can run, C-c is not a prefix, because it goes to the program that is running there. The keys C-c x, C-c s and C-c t are never given to a mode, and are left for your own commands.

SPC in NORMAL state is the leader, a prefix that belongs to you. As Tuatara comes, nothing is under it. You put there the keys that you use most, in the places that suit you, and nothing the editor updates will move them. C-x SPC opens the same keys in every buffer and in both states, so that the leader works in INSERT state too. If another key suits you better than SPC, set *leader-key* to it, for example ",". How to bind keys is the subject of chapter 20.

C-h is the family of help, described below.

Two more prefixes you meet in NORMAL state are g, which starts moves such as g g (non-modal: M-<) for the top of the buffer, and m, which starts the selecting keys of chapter 5. They work the same way, and the key hints show them.

Tuatara has a setting that turns the modal states off. With *modal-editing* set to nil every key writes text as it does in a plain editor, and the Control and Meta keys do the commands. The prefixes in this section work in the same way. C-z is a prefix of its own for this: under it are the commands of NORMAL state's selecting, cursor, spelling and replacing keys, on the same letters (C-z m f for m f), and the key hints list them.

8.5 Key hints

Press a prefix key and wait a moment. Under the text, a panel opens that lists every key that can come next with the name of its command. You do not need to remember the keys of a family; you need only remember the first key. Figure 8.2 shows the panel after C-x in a buffer that visits a letter.

The names that start with a plus sign are further prefixes, and pressing their key opens another panel one level down. A key whose command cannot run in the buffer you are in is dimmed, and pressing it tells you why. C-g closes the panel. If the keys do not all fit, the last row ends in … and says that C-h lists them all.

C-h pressed right after any prefix key lists every key under it in a buffer of its own, the prefixes unfolded, so that you can read them at leisure: C-x C-h for the global keys, C-c C-h for those of the buffer you are in. q closes that buffer.

A panel of hints takes as many rows as the frame has room for. If you want it shorter, set *key-hint-rows* to the most rows it may take. The panel's colours are the faces below.

Try it, with the keys of a buffer you do not know

  1. Press C-x C-b to open the list of buffers. The cursor is in it.
  2. Press C-c and wait a moment. The panel lists what the list can do: mark a buffer, mark it for deletion, open one and so on, each with its key.
  3. Press C-g. The panel closes and nothing was run.
  4. Press C-c C-h. The same keys are listed in a buffer of its own, in a window beside the list, and the cursor stays in the list. Press C-x o to move to it and q to close it, then q again to close the list of buffers.
  5. Press C-x and wait. Press w to see what is under C-x w, then C-g.

8.6 Menus

Some commands have more to say than one key can. Git's commit command has switches, options and several ways to finish. For these Tuatara opens a menu: a panel of the same kind as the key hints, but with a title, and with keys that are not all commands. There are three kinds of entry. An option asks you for a value, such as a number of commits, and keeps the menu open too. 8.7 Asking what a key does

You press a key by accident and something happens, or you see a key in a book and want to know what it is. C-h k answers. It waits for a key or a longer key and then shows, in a window of its own, the command the key runs, what the command does and where the command is defined. You do not need to leave the key you were using; the question is answered the moment the key is complete.

C-h k takes a prefix as well. Press C-h k, then C-x, and it waits for the rest, then shows C-x C-f when you press C-f. A key with no command says it is undefined.

? in NORMAL state, or C-h b anywhere, lists every key that is in effect in the buffer you are in. The list goes keymap by keymap, the one for this buffer first and then those it falls through to. A key that a mode has taken away is shown as (none here). It is a long list, but a search with C-s finds a key or a command in it.

Try it, when you forgot what a key does

  3. Press C-x 1 (modal: F) to leave only one window. Press C-h k again, and this time press C-x and then C-s. It names save-buffer.
  4. Press ? (non-modal: C-h b) to see every key in force. Press C-x o to move into the list, then C-s, type save and RET to find the keys for saving. Close the list with q.

8.8 Asking what a command does

C-h x asks for a command by name, with the same list as M-x, and shows the command: what it does, which keys run it and in which file it is defined. You use it when M-x offered a command whose first line was not enough, or when you want to see the keys that a command has so that you can learn them. Every command is offered, including those that belong to other kinds of buffers. The file in the last line is a link. Press RET on it and the source opens beside the help, with the cursor on the definition. A release carries its Lisp sources, so this works in the AppImage and the distribution packages too.

C-h f is the same for any function of Lisp, not just for the commands. It shows the parameters as well. It is for people who write their own commands. In a Lisp buffer it offers the name at the cursor first.

C-h v does the same for a variable. A setting is a variable, so this is how you ask what a setting is for and what it is now. Press C-h v, type *fill-column* and RET, and the help gives the value, 80 as Tuatara comes, and what it is for. A very long value, such as a list of hundreds of items, is cut after a few thousand characters, and says so. For a setting, a line of its own says which values it takes: t, nil for one that is on or off, the words it understands, or a kind of value such as a whole number or text. 8.9 Finding a command when you do not know its name

You know what you want, such as turning a line of text into capital letters, but not what it is called. Here are three ways to look.

The first is M-x itself. Type a word that is likely to be in the name and read the list. Words may come in any order, so upper and case together find the commands with both. The list shows the first line of what each one does, which is often enough.

The second is C-h a, apropos. It asks for words and searches both the names and the documentation of every command and setting, which finds things that M-x cannot, because the word you chose is in the help and not in the name. The matches appear in a buffer called *Apropos*, the commands first and then the settings, with the first sentence of each one's help. Each name is a link: RET on it shows its full help, and TAB goes to the next name.

The third is the keys. ? (non-modal: C-h b) lists everything that has a key, and C-c or C-x with a wait shows what a family offers. A command that has a key has usually been put there because it is common.

Try it, to find how to make words capital

  1. Press C-h a, type capital and press RET. The *Apropos* buffer lists the commands and settings that mention capital letters.
  2. Press TAB until a name you like is selected, and RET on it. Its help opens.
  3. Close the help with q, and the list with q again.
  4. Press M-x and type upcase. The list shows the commands that change to upper case, and the keys of those that have one.
  5. Press C-g.

8.12 The tutor and manual pages

M-x tuatara-tutor opens the tutor, a buffer that teaches the modal keys by making you use them. It is an ordinary buffer with its own instructions. Each lesson tells you what to type and gives a line to practise on, marked with an arrow, and the keys it names are the keys you really have, even if you moved them. You edit the tutor as it says, and nothing you do in it is saved. Half an hour with it is the quickest way to get used to the two states. The page *About Tuatara* below has a button that opens it.

The system's own manual pages, the ones that explain programs such as ls or grep in a terminal, can be read in Tuatara. M-x man asks for a name, as in ls, ls(1) or 1 ls, and lists the names of the pages the system has as you type. The page opens read-only in a window of its own, laid out for the width of the window, with its headings, bold text and underlined text drawn in faces. Every mention of another page, such as chmod(1), is a link. If you open the source of a page, a file such as tool.1, M-x man offers that file first, so that you can see what you wrote as it will look.

The page is made by the system's man and groff, run with no network and none of your files, and it is in English. If they are not installed, M-x check-health says so.

8.15 Lisp in the running editor

Tuatara is written in Common Lisp, and the Lisp you type runs inside the editor. This is how an init file works. It is also a calculator, a way to look at a value and a way to try something small. You do not need Lisp for any other chapter, so you may skip this part.

M-: asks for one Lisp expression in the minibuffer and shows its value, in any buffer. M-: (+ 2 3) RET shows 5. In a Lisp buffer, such as *lisp-scratch* (chapter 7) or a file that ends in .lisp, C-x C-e runs the expression before the cursor, C-j puts what it printed on the lines after it, and C-M-x runs the whole top-level form the cursor is in. M-x eval-region runs the selection, and M-x eval-buffer runs the whole buffer. They run only in Lisp buffers, and run nothing in a file opened with care because you do not trust it.

M-x ielm opens *ielm*, a buffer with a prompt where you type Lisp and read the answer below. RET runs the input when it is whole expressions and starts a new line when it is not. If Lisp meets an error, the echo area says what it was. M-x toggle-debug-on-error makes it show the calls under way too, in *Backtrace*. That is for people who write Lisp, and is easy to leave off.

8.16 Binding keys yourself

The prefixes, the leader and the labels that the key hints show are yours to set. You can bind a key to any command, and give it a label that the hints show in place of the command's name, in your init file. That is described in chapter 20, together with the settings that move the leader.
